Decision summary

Reuse the existing Spring Boot engine, expose it via 4 JSON endpoints. Browser → Netlify Function (BFF) → Spring Boot via HMAC-SHA256 signed requests. Spring Boot handles payment, plan numbers, SOAR writes, commission ledger. Supabase keeps marketing/dashboard data + a writeback cache of plan_number. No user JWT crosses into the engine. The browser never talks to the engine directly.

Invariants (no se rompen)

⚠ Money rules · auth rules · data flow rules

  • Spring Boot = canonical source for money. Plan numbers, commission ledger, payouts. Never duplicated in Supabase.
  • Supabase = canonical source for marketing/auth. Leads, partners (identity), dashboard data, plan_number cache.
  • HMAC secret never in client JS. Lives in Netlify env vars + Spring Boot env vars only.
  • User JWT never crosses into Spring Boot. Netlify Function validates JWT, then talks to engine using its own HMAC identity.
  • Stripe Connect onboarding return URL points to thedesignerplan.com, NOT designerplan.io anymore.
  • The Spring Boot continues to serve designerplan.io until cutover (we don't break the old site).
  • All money writes are idempotent. Stripe webhook may fire twice — engine handles dedup.

here

Slide-out checkout panel (replaces cart drawer)

Pending

Spec: Ant Design Drawer (448px from right) triggered by "Buy Now" on any plan tile. Single plan, customer entry, live price recalc, Stripe Elements card field, payment submit.

Layout
Header (sticky): plan name + close button. Body (scrollable): plan summary (image, description), "Items covered" text input (e.g., "iPhone 14 Pro + AirPods"), "Retail value" number input ($), live price display. Footer (sticky): price breakdown (retail + plan cost + protection premium), Stripe Elements card field, "Pay $X.XX" CTA button.
Behavior
Open: drawer slides in (plan pre-populated from tile). Fill form: on blur of retail_value field, POST to BFF with { plan_id, items_covered, retail_value_cents } → BFF calls Spring Boot POST /api/v1/checkout → server returns amount_cents + commission details → update live price display. Error: if BFF fails, show "Unable to calculate price. Please try again." + disable submit. Submit: POST final checkout request to BFF → receive client_secret → load Stripe Elements + show card field → user confirms payment → close drawer on success.
Validation
Client-side: items_covered required (minlength 3), retail_value required + > $1. Show field-level error messages inline. Server-side: Spring Boot re-validates + re-prices (tamper-proof). If price mismatch, return 422 business_rule_violation.
States
Idle: drawer open, form ready. Loading: during price calc or payment submit, disable inputs + show spinner. Error: show error message, allow retry. Stripe Elements: after price confirmed, mount Stripe card field (test mode only until Wave E.17).
Mobile
Drawer 100% width on screens <768px. Touch-friendly buttons (min 44px height). Keyboard-accessible inputs + focus visible on all interactive elements. On iOS, use inputmode="decimal" for numeric fields.
Testing
Playwright E2E: happy path (open drawer → fill items + value → price updates → submit → see Stripe Elements). Error scenarios: network failure during price calc, validation failure (empty fields), Stripe element failure (invalid card). Manual: test on mobile device, verify accessibility with keyboard nav.
Files
designer-plan-site/plans/index.html (attach click handler to "Buy Now" buttons), designer-plan-site/js/checkout-drawer.js (new module: Drawer state, form validation, BFF calls, error handling, Stripe Elements mount)
